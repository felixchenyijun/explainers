GPUs & TPUs: how the work gets done

GPUs and TPUs turn large amounts of numerical work into parallel computation: GPUs organize many programmable thread groups, while TPUs emphasize specialized tensor dataflow—and both use dedicated matrix hardware.

GPU = graphics processing unit. TPU = Google’s tensor processing unit. Start with the map; then move real numbers through an array and experiment with the limits.

The central tradeoff is how to keep arithmetic busy. A GPU can switch among ready warps while other warps wait. A TPU’s matrix engine reuses data through a regular array. Both still need enough parallel work, well-shaped tiles, fast memory, and an effective compiler.

These are tendencies, not hard categories. CPUs have vector and sometimes matrix extensions. GPUs contain specialized hardware. TPUs are programmable through a software stack. The GPU side of the map uses NVIDIA terminology; AMD and other vendors organize and name their hardware differently.

No universal winner follows from this table. Compare the same model, numerical quality, batch size, latency target, software version, and complete system. Peak FLOP/s and core counts alone do not settle it.

Follow one neural-network layer, then training and inference

For a simple linear layer, Y = XW + b. X holds input features or activations; W holds learned weights; b is a bias. Each row of X may represent a token or an example. The output feeds the next operation.

1 · Stage tilesBring pieces of X and W from device memory into local storage.
→
2 · Multiply + accumulateCompute many dot products, reusing the same inputs.
→
3 · Finish the operationAdd bias and perhaps an activation; fusion can avoid an intermediate round trip.

4 · ContinueStore Y or keep part of it close for the next fused operation.

Training runs a forward pass, computes a loss, propagates gradients backward, and updates weights with an optimizer. It needs storage for gradients, saved activations or recomputation, and often optimizer state. For the matrix part, backward work includes products like dX = dY Wᵀ and dW = Xᵀ dY. Modern GPUs and Cloud TPUs support this.

Inference uses already learned weights. In an autoregressive language model, prefill processes the prompt, and decode repeatedly generates another token. Prefill offers parallel work across prompt tokens. A single request’s next token depends on prior generated tokens; batching requests can expose more parallelism and weight reuse. Attention and its key/value (KV) cache add their own traffic and capacity costs.

Throughput and latency are different goals. A larger batch can produce more tokens per second overall while making an individual request wait longer. The best operating point depends on the experience you want.

Memory hierarchy: why moving a number can cost more than multiplying it

On-chip registers and SRAM are small and close; DRAM provides much more capacity. A useful mental model is a small workbench beside a larger storeroom. The workbench is valuable because the same parts can be used repeatedly without another trip.

For C = AB, one A element contributes to many columns of C, and one B element contributes to many rows. Tiling divides the arrays into blocks that fit near the compute units. Load a tile, reuse it for many multiply-adds, and write a result tile. Both GPUs and TPUs do this.

Capacity asks whether the working state fits. Bandwidth asks how many bytes can move per second. Latency asks how long one dependent access takes. Caches and explicit buffers reduce traffic; concurrent requests and overlapping work can hide some latency. None makes memory free.

At system scale, a tensor may also travel between chips. That creates another hierarchy: local storage, device memory, neighboring accelerators, then the broader network. An operation efficient on one chip can become communication-heavy after it is partitioned.

Each square is a processing element (PE): a multiplier and an accumulator. Its sum starts at zero and stays in place while pairs of inputs arrive.

Stagger the arrivals. A's row 1 starts one tick after row 0; row 2 starts two ticks after it. B's columns have the same delays. This makes matching pairs meet at every square.

Reuse a value in space. An A value visits three PEs in its row. A B value visits three PEs in its column. Neighbors pass them along; the array does not fetch every multiplication's inputs separately from distant memory.

From one multiply-add to a large neural network

For A of shape M × K and B of shape K × N, C has shape M × N. The shared dimension K must match. Each entry is C[i,j] = Σₖ A[i,k] B[k,j]: one row meets one column, and K products become one sum.

A multiply–accumulate (MAC) updates a running sum: s ← s + a × b. In performance accounting it usually counts as two operations. A floating-point fused multiply-add performs the multiply and add with a single final rounding; its instruction count can be one while its FLOP count is two. Matrix hardware may use its own specified numerical behavior.

An isolated tiny array has startup and finishing costs. Large jobs use many tiles, and implementations can overlap transfers and computation. The compiler or kernel must also handle edges when dimensions do not fill a tile. Padded or masked work may consume hardware capacity without increasing useful output.

The important reuse appears in both architectures. A GPU kernel might stage operand tiles in shared memory and issue Tensor Core instructions. A TPU program might stage tiles for an MXU. A diagram of a systolic array explains one powerful dataflow idea; it does not reveal the internal circuitry of every matrix instruction.

Precision: FP32, FP16 and BF16 are different compromises

A floating-point number stores a sign, an exponent for scale, and a fraction for detail within that scale. Think scientific notation: the exponent controls range; the fraction controls how finely nearby values can be distinguished.

FP32 uses 4 bytes. FP16 and BF16 use 2 bytes. BF16 keeps an FP32-like exponent range but has fewer fraction bits than FP16. Around 1, adjacent representable normal numbers are spaced by 2⁻²³ in FP32, 2⁻¹⁰ in FP16, and 2⁻⁷ in BF16.

Reduced precision can cut traffic and let hardware perform more arithmetic per unit area and energy. It also rounds away information. Mixed precision often uses lower-precision inputs and higher-precision accumulation. FP32 accumulation helps preserve the sum; it cannot recover detail already lost when the inputs were rounded.

INT8, FP8 and other formats introduce further tradeoffs. Integer quantization uses a scale, and sometimes a zero point, to map values into a smaller set. Calibration, rounding, and model sensitivity matter. Supported modes depend on chip generation and operation; use a peak throughput number only with its stated precision and sparsity conditions. What the roofline leaves out—and how to reason about a real workload

The roofline is a ceiling, not a promise. The point in the lab is the ideal attainable bound under its assumptions; it is not a measurement. A real operation can lie well below the line.

First ask what is on the critical path. Is there enough independent work? Does a single operation last long enough to amortize dispatch? Do the matrix shapes fill the hardware? Are dependencies forcing the next operation to wait? Would fusion eliminate unnecessary intermediate memory traffic?

Then account for the complete model. Weights, activations, KV cache, gradients, and optimizer state impose different traffic and capacity requirements. Reusing a weight does not eliminate the cost of attention, reductions, or non-matrix operations. A GPU or TPU can be compute-limited in one layer and bandwidth- or communication-limited in another.

Scaling adds new limits. Gradients may need an all-reduce: each worker’s contributions are combined and the result is distributed. Tensor-parallel layers exchange intermediate tensors. Pipeline partitions can wait in “bubbles” between useful work. More links or chips help only the parts that use them effectively.

Measure the target experience. Compare useful throughput, response latency, numerical quality, memory use, and system cost using the same workload and a warmed-up software path where appropriate. Include compilation and startup when your actual usage pays those costs. The lab intentionally avoids vendor rankings and current chip specifications.

Quick glossary: the terms that carry the explanation
TensorAn array indexed along one or more dimensions: a vector, matrix, or higher-dimensional collection.
ActivationA value produced while processing an input, such as a layer’s output; different from the learned weights.
KernelA device function or compiled unit of work. A GPU kernel typically runs many logical threads.
Warp / SIMTNVIDIA’s 32-thread execution group / single instruction, multiple threads. Other vendors use other names and sizes.
SMA streaming multiprocessor: scheduling, execution, and local storage repeated many times in a GPU.
MAC / FLOPs / FLOP/sMultiply–accumulate / amount of floating-point work / rate of doing that work. A MAC conventionally counts as two operations.
TileA manageable submatrix used to fit local storage and execution shapes.
Systolic arrayA regular network of compute elements that passes data between neighbors in a coordinated flow.
SRAM / DRAM / HBMStatic RAM, often used on-chip / denser dynamic RAM / stacked DRAM with a high-bandwidth interface.
Arithmetic intensityUseful arithmetic per byte moved across a specified memory boundary. The lab uses HBM traffic.
Reduction / collectiveCombining many values, such as a sum / an operation involving a group of devices, such as an all-reduce.
UtilizationHow much of a resource’s available capability does useful work. The precise metric depends on the resource and measurement.
