01The token machine

Weights are learned during training and stay fixed during ordinary inference. The hidden states and KV cache are temporary, request-specific state. The model is a function; generation is the loop around it.

Under the hood · from UTF-8 to one decoder block

A tokenizer maps text to integer IDs using a fixed vocabulary, often subword or byte-based pieces. One word can be several tokens; spaces and punctuation matter. Chat templates add role delimiters and special tokens. Embedding is a lookup: X = E[token_ids], giving one d_model-dimensional vector per position. Detokenization turns emitted IDs back into text, sometimes buffering incomplete byte sequences.

For a common pre-norm, RoPE, gated-MLP decoder, one block looks like this (architecture details vary):

X ∈ ℝ[T × d_model] // omit batch axis Z = RMSNorm(X) Q = RoPE(Z Wq); K = RoPE(Z Wk); V = Z Wv A = softmax(Q Kᵀ / √d_head + causal_mask) V // per query head Y = X + concat_heads(A) Wo // residual connection U = RMSNorm(Y) X_next = Y + (SiLU(U Wgate) ⊙ U Wup) Wdown // gated MLP logits = RMSNorm(X_final[last_position]) W_vocab

Attention mixes positions; the MLP mixes features at each position. Both contain learned projections. Normalization keeps activation scale controlled; residual connections preserve an additive stream across depth. RoPE rotates Q and K by position so their dot product depends on relative displacement. It is not a guarantee of reliable extrapolation beyond trained context.

With query heads Hq and KV heads Hkv, Q has shape [Hq, T, dh]; K and V have [Hkv, T, dh]. MHA uses one KV head per query head; GQA shares each KV head among a group of query heads; MQA shares a single KV head. Those are checkpoint design choices.

Training processes known next tokens in parallel and computes gradients. Inference usually does neither backpropagation nor an optimizer update. LoRA changes the effective weights; retrieval adds context; neither is what an ordinary KV cache does.

Why the cache is mathematically valid

In a causal model, a past position cannot depend on future tokens. Its K and V therefore stay unchanged when the prefix grows. Store them at every layer; compute only the new position’s Q/K/V and MLP, then append its K/V.

The new query still reads the stored K/V. Caching removes repeated projections and past-position computation, not the need to attend to history. Q is not cached because future positions use their own queries.

a_t = softmax(q_t K_≤tᵀ / √dh) o_t = Σⱼ≤t a_tj v_j cache[layer].append(k_t, v_t)

For the visual only, V is two-dimensional: The [1,0], capital [0,1], of [0.5,0.5], France [2,1], is [−1,1]. The displayed result is their weighted sum. Real head vectors have many more coordinates.

Without KV reuse, each step reruns the whole prefix. With it, a dense-attention decode step has attention work linear in current context length; generating a long sequence still accumulates quadratic attention work overall.

Temperature, nucleus sampling, and stopping
p_i = exp((z_i − max(z)) / T) / Σⱼ exp((z_j − max(z)) / T)

Subtracting the maximum avoids overflow without changing probabilities. At T = 0, use argmax directly: it is a greedy-decoding convention, not division by zero. Top-p retains the smallest sorted prefix whose cumulative probability reaches p; top-k instead keeps a fixed count.

Lower temperature sharpens the existing preference; it does not teach the model new facts. Beam search keeps multiple partial sequences and favors sequence likelihood, which is not necessarily correctness. Structured-output decoding can mask invalid next tokens according to a grammar.

Stop on an end token, a stop condition, or a token limit. Streaming sends completed text pieces as tokens arrive; it improves perceived latency without making the underlying model faster.

The first token is different. Prefill processes all known prompt positions in parallel within each layer and samples the first output. Decode feeds that output back in, one position per request per iteration. You cannot ordinarily compute a future token before choosing the token it depends on.

02Where the time actually goes

The GPU has fast arithmetic, a small on-chip working area, and much larger high-bandwidth memory (HBM). A token can spend more time waiting for weights and KV than multiplying them. Batching reuses the same weights across requests.

P = 8 × 10⁹ approximates parameters used in matrix multiplies. Multiply-add counts as two FLOPs. Attention contributes both QKᵀ and AV, using query heads. Weight reads are shared across the batch; KV reads grow with it. Ignoring KV and activation traffic, BF16 linear layers have arithmetic intensity about B FLOP/byte.

This is an optimistic single-device model: one weight read and one KV read per step, ideal reuse, no kernel-launch overhead, no communication, no softmax/norm cost, no new KV writes, and no temporary buffers or quantization metadata. The result is a modeled lower bound, not achieved latency. Effective compute stays fixed when bits change; real low-bit kernels may be faster or slower. A payload below 80 GiB is necessary, not sufficient, to fit.

Real shapes matter: tiny matrix-vector operations may underuse compute units; larger matrix-matrix operations often do better. Long-context attention can dominate either phase. FlashAttention and hardware caches change traffic, while sparse/windowed attention and latent KV representations change the cost model itself.

Two clocks, two user experiences.

TTFT is time to first token: queueing + uncached prefill + first sample. Inter-token latency is the gap between streamed tokens. Aggregate tokens/s measures service throughput; it can rise while individual users wait longer.

A useful debugging order.

Separate queue time, prefill, and decode. Then inspect memory capacity, bandwidth, compute utilization, and communication. Compare p50 and p95 under realistic arrival rates, input lengths, and output lengths.

From a request to a running GPU kernel

A server tokenizes the request, looks up reusable prefix blocks, reserves cache space, and schedules work. The runtime maps tensor operations to GPU kernels. Fused kernels avoid writing intermediates to HBM; optimized attention tiles data through on-chip memory; graph replay can reduce host launch overhead. The sampler produces a token, the server streams it, and the scheduler chooses the next iteration’s requests.

Weights generally stay resident in device memory between iterations. “Read weights every step” refers to feeding compute from HBM, not reloading a checkpoint from disk or the CPU. Offloading to host RAM can make a larger model fit, but adds transfer and synchronization costs.

With N output tokens, generation time is roughly TTFT + (N − 1) × mean inter-token latency, plus transport effects. Output-token budget is therefore a direct latency and cost knob. A long prompt and a long answer stress different parts of the service.

03Every technique removes a different kind of waste

Ask what resource is scarce, and what contract can change. Scheduling and exact reuse preserve the computation’s meaning. Quantization changes numerical precision. Search and reasoning intentionally spend more work to seek a better answer.

How exact speculative sampling stays exact

Let p be the target distribution and q the draft distribution at the same prefix. For a draft token x ~ q:

accept x with probability min(1, p(x) / q(x)) first rejection → draw replacement from normalize(max(p − q, 0)) all accepted → draw one bonus token from target p

For q(x)=0.50 and p(x)=0.30, accept with probability 0.60. The correction redistributes rejected probability mass. Discard the speculative suffix after the first rejection: its conditionals assumed a prefix that no longer exists.

Use the actual decoding distributions after temperature/filtering. Correct acceptance and correction preserve the target distribution, not necessarily the same output for a fixed random seed. Simply keeping tokens the target “likes” is not exact sampling. The slider depicts possible outcomes, not a simulated acceptance probability.

Accepted tokens plus one correction/bonus advance the output, subject to stopping conditions. Target verification can reuse weight reads across positions; drafting is still work. Large batches, poor acceptance, or expensive verification can eliminate the benefit. Original algorithm and proof.

Memory deep dive · FlashAttention, paging, and prefix reuse

FlashAttention: change the calculation’s working set.

Softmax seems to require the whole row. It does not: maintain a running maximum, normalizing sum, and weighted-value accumulator. When a new tile raises the maximum, rescale old accumulators. This yields the same dense attention mathematically, with ordinary floating-point differences.

m′ = max(m, max(scores_tile)) ℓ′ = exp(m−m′) ℓ + Σ exp(scores_tile−m′) o′ = exp(m−m′) o + Σ exp(scores_tile−m′) v final attention output = o / ℓ

Paging: change where persistent state lives.

Logical request blocks: [0] [1] [2] Block table: ↓ ↓ ↓ Physical GPU blocks: [7] [2] [9] Shared prefix: request A → [7] [2] [9] request B → [7] [2] [4] shared private suffix

No need to reserve one giant contiguous buffer for a guessed maximum output length. Allocate blocks as tokens arrive, reclaim finished sequences, and share immutable prefix blocks. Partial blocks and metadata still consume space; writes to shared state need copy-on-write or equivalent safeguards.

Prefix reuse requires the same preceding tokens, model weights, positions, and relevant execution configuration. The same paragraph later in a different conversation is not the same cache entry. Prefix caching avoids computing those tokens again, but decode still attends to their K/V.

These techniques compose: paging manages persistent KV placement; FlashAttention manages the working set of an attention calculation.

Numerics deep dive · what 4-bit actually means

Quantization maps real values to a smaller discrete set, usually with scales per group or channel. A simple symmetric form is q = clamp(round(w/s), q_min, q_max); reconstruct ŵ = s × q. Outliers can force a coarse scale that damages small, meaningful values. Calibration and methods such as AWQ choose quantization parameters to limit harmful error.

Toy scale s = 0.2, signed 4-bit range [−8, 7] weights: [−0.91, 0.08, 0.73, 1.20] integer codes: [ −5, 0, 4, 6] reconstructed: [−1.00, 0.00, 0.80, 1.20]

W4A16 means 4-bit weights and 16-bit activations. KV precision is independent. “4× smaller” compares ideal 4-bit versus 16-bit weight payload; scales, zero points, padding, and unquantized tensors reduce that saving. Low-bit weights may be unpacked and dequantized inside kernels. Fewer stored bits do not automatically mean faster arithmetic.

Evaluate task accuracy, long-context behavior, outliers, throughput, and latency on the actual kernels. Quantization error is a model-quality tradeoff, unlike exact caching. AWQ · GQA architecture.

In a mixture-of-experts model, only selected experts run for each token. Active parameters help estimate arithmetic; total parameters matter for weight residency. A batch may touch many experts in aggregate. MoE does not make a large total checkpoint take the memory of its active parameter count.

Beyond speed · reasoning tokens, best-of-N, search, and verification

There are two different optimization problems: make the same model distribution cheaper to sample, or spend a fixed budget on better answers. Exact speculation targets the first. Inference-time compute targets the second.

Serial reasoning: prompt → intermediate tokens → answer Parallel sampling: prompt → N candidates → select or vote Search / revision: candidate → verifier / tools → revise or branch

Longer reasoning uses more sequential decode and cache. Parallel candidates offer parallel work but increase total tokens and memory. Verifiers, tests, and tools can help select useful answers; a weak verifier can reward plausible mistakes. More tokens or more candidates are not a monotonic guarantee of better results.

Retrieval changes the evidence in the prompt; tool calls add external computation and round trips. Distillation trains a smaller model to imitate a larger one, shifting cost from serving to training. Evaluate answer quality per dollar or per latency budget, not only raw tokens/s. Research on allocating test-time compute.
